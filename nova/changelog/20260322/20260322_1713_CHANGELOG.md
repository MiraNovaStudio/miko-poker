# Fix stale pot award animations playing after alt-tab — 20260322.1713

## Summary
Fixed an issue where pot award animations (chip count spin-up, chip overlay pulse) would play when alt-tabbing back to the game, even if the hand had already moved forward. The root cause: `requestAnimationFrame` pauses when the tab is hidden but `setTimeout` callbacks continue (throttled), so the game state advances. When the tab regains focus, rAF resumes and the pot-fly animation's completion handler fires `pulseChipOverlay()` and `animateChipsTo()` — starting fresh visible animations from stale data.

Fix: both `animatePotToWinners` and `animateSinglePotAward` now capture the game `generation` counter. If the generation has changed by the time the animation completes (meaning a new hand started), the visual elements are cleaned up immediately without triggering the pulse/spin-up effects.
