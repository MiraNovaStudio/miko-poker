# Fix all-in skipping human player action — 20260314.2054

## Summary
Fixed a bug where the human player's turn was skipped when an AI went all-in. The all-in runout condition used `canActPlayers.length <= 1` which incorrectly triggered the auto-runout when exactly one player (the human) could still act. Changed to `=== 0` so the board only auto-runs when no one has a pending decision.

## Files Changed

### Modified
- **miko-ui/src/managers/GameManager.ts** — Changed all-in runout condition from `<= 1` to `=== 0` so the last player who can act still gets their turn before the board runs out.

## Test results
- UI-only change, no engine tests affected.
