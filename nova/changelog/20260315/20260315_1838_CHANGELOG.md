# Refactor PotManager for correct side pot tracking — 20260315.1838

## Summary
Refactored `PotManager` to track per-player contributions across all betting streets, enabling accurate side pot layer computation during gameplay — not just at showdown. Previously, `collectBets()` collapsed all bets into a flat `mainPot` number, making `getSidePots()` always return empty. Now the pot manager maintains a contributions map that `getSidePots()` and `getMainPot()` use to compute layered pots on demand. The `awardPots()` algorithm is unchanged but now reads from stored contributions instead of reconstructing from player objects. All 191 existing tests pass with no changes.

## Files Changed

### Modified
- **engine/src/pot.ts** — Replaced `mainPot`/`sidePots` fields with `totalCollected` + `contributions` map. `collectBets()` now updates contribution tracking. Added `computeLayers()` private method used by `getSidePots()`, `getMainPot()`, and `awardPots()`. API surface unchanged.

### Added
- **engine/tests/pot-layers.test.ts** — 13 new tests covering: `getSidePots()` visibility during gameplay, multi-street contribution accumulation, the bug report scenario (A=50 all-in, B/C=200), split pots with side pots, fold-on-later-street tracking, and 8-player chip conservation.

## Test results
- `npm test`: 12 suites, 191 tests passed (103 engine + 88 UI).
