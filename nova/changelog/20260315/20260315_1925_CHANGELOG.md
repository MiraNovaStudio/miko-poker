# Sequential side pot awards — 20260315.1925

## Summary
Implemented sequential per-pot winner display for multi-pot scenarios (side pots). Previously all winners were shown simultaneously with a single "WINNER!" label, making it unclear who won which pot. Now each pot is awarded one at a time — side pots first, then main pot — with its own status message, WINNER! label, and chip-fly animation. Single-pot hands are unchanged.

### Engine changes
- `PotManager.awardPots()` now returns `PotAwardResult[]` with per-pot winner info (pot index, amount, winner IDs).
- Added `GamePotResult` type carrying per-pot label, amount, winners, and hand name.
- `GameResult.potResults` is populated when there are multiple pot layers (side pots).
- `doShowdown()` captures per-pot results and includes hand names for each pot's winning hand.

### UI changes
- `onHandComplete()` branches on `result.potResults`: multi-pot scenarios use sequential display with 2.5s stagger per pot; single-pot uses existing logic.
- Added `animateSinglePotAward()` method for per-pot chip-fly animation.
- Next-hand delay increases automatically to accommodate sequential pot display.

## Files Changed

### Modified
- **engine/src/pot.ts** — Added `PotAwardResult` interface; `awardPots()` returns `PotAwardResult[]`
- **engine/src/game-engine.ts** — Added `GamePotResult` interface; `GameResult.potResults` field; `doShowdown()` builds per-pot results
- **engine/src/index.ts** — Exports `GamePotResult` and `PotAwardResult` types
- **miko-ui/src/managers/GameManager.ts** — Sequential pot display in `onHandComplete()`; new `animateSinglePotAward()` method; dynamic next-hand delay
