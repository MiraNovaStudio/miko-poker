# Fix ALL IN label persisting after uncalled bet returned — 20260321.0827

## Summary
When a player went all-in and got called but received an uncalled bet portion back (giving them chips > 0), the chip overlay still showed "ALL IN" instead of their actual chip count. The engine correctly marked the player as no longer all-in after returning the excess, but the UI slot's `_allIn` flag was never cleared. Now `updateAllChipLabels()` checks the engine's all-in state and clears the ALL IN label when the player has chips returned.

## Files Changed

### Modified
- **miko-ui/src/managers/GameManager.ts** — `updateAllChipLabels()` now calls `slot.clearAllIn()` when the engine reports the player is no longer all-in, before setting the chip amount
